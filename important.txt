useful docker command
    docker stop pg-database	Graceful stop (Postgres shuts down cleanly). Container is kept — just not running.
    docker start pg-database	Start it back up later. Data is still there.
    docker restart pg-database	Stop + start in one go.
    docker ps	See what's currently running.
    docker ps -a	See all containers (running + stopped).
    docker rm -f pg-database	Delete the container entirely (volume still keeps the data — you can docker run again and reattach it).
    docker volume rm ny_taxi_postgres_data	Delete the data volume. Only do this if you want to wipe the database.

daily command

Daily workflow (every time you start your PC)
1. Start Docker Desktop

Wait until Docker Desktop says "Engine running".

2. Start your PostgreSQL container

Open PowerShell:

docker start pg-database

Verify it's running:

docker ps

You should see:

pg-database    Up
3. Activate your virtual environment

Go to your project:

cd C:\Users\Admin\dataengineeringZOOMCAMP\test\pipeline

Activate it:

.\.venv\Scripts\activate

You should see:

(.venv) PS C:\Users\Admin\dataengineeringZOOMCAMP\test\pipeline>
4. Start Jupyter
jupyter notebook

or

uv run jupyter notebook

(if that's how you've been starting it).

5. Test the database connection

Run this once in a notebook:

import psycopg2

conn = psycopg2.connect(
    host="127.0.0.1",
    port=5432,
    database="ny_taxi",
    user="root",
    password="root"
)

print("✅ Connected!")
conn.close()

If that works, you're ready to continue.

Using SQLAlchemy

Now that the Windows PostgreSQL service is stopped, this should work after restarting the Jupyter kernel:

from sqlalchemy import create_engine

engine = create_engine(
    "postgresql://root:root@127.0.0.1:5432/ny_taxi"
)

with engine.connect() as conn:
    print("✅ SQLAlchemy Connected!")

If it still fails while psycopg2.connect() succeeds, restart the Jupyter kernel (Kernel → Restart) and run only the SQLAlchemy cell again. The notebook may still be holding onto a stale connection from before we fixed the service conflict.

Quick commands you'll use most often
# Start Docker container
docker start pg-database
